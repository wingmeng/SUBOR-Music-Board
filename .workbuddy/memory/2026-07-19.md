## 修复音符键长按不持续输入的 bug

- **文件**：`src/components/NotationGrid.vue`
- **问题**：按住允许输入的键（如 1-7）不放时，`onDocumentKeydown` 中 `if (e.repeat) { preventDefault(); return }` 直接吞掉浏览器 repeat 事件，导致只有首次按下输入一次，之后不再输入。
- **修复方案**：自定义长按重复定时器，不依赖系统键盘重复率
  - 首次按下立即 `commitNoteChar(char)` 写入一次，并启动定时器
  - `NOTE_REPEAT_INITIAL_DELAY=350ms` 后开始重复，`NOTE_REPEAT_INTERVAL=110ms` 间隔持续写入并推进光标
  - `onDocumentKeyup`：松开按键立即 `clearNoteRepeat`
  - 边界停止：到达最后一列、开始播放（`watch(isPlaying)`）、对话框打开、组件卸载
  - 多键切换：按下新键时 `clearTimeout` 旧定时器，启动新键的重复
- **未改动**：`NoteCell.vue` 的 `e.repeat` 阻止逻辑保留，作为阻止 input 元素插入字符的第一道防线（事件仍冒泡到 document 由定时器接管）
- **验证**：`pnpm exec vue-tsc -b` 类型检查通过

## 修复羽毛笔书写动画消失的回归

- **背景**：长按重复输入修复后，用户报告输入时羽毛笔动画消失
- **根因**：工作区此前的重构把音符输入从 grid 内 `@keydown="onKeydown"`（只处理方向键/Insert，音符字符走 NoteCell `input` 事件 → `onNoteInput` → `processInput` → `quill.startWriting()`，有动画+声音+队列）改为 document 级 `onDocumentKeydown` 并新增音符字符的 `preventDefault` + 直接 `setNote/insertNoteAt`（绕过了动画路径）。我的 `commitNoteChar` 起初沿用了这条无动画路径。
- **修复**：`commitNoteChar` 改为调用 `onNoteInput(props.cursor.voice, char)` 走标准输入路径，动画/声音/队列全部回归
- **长按与动画协调**：书写动画 `write` 200ms，重复间隔 110ms，动画期间到达的重复输入自动进 `inputQueue`，`handleQuillAnimationEnd` 动画结束时批量写入并推进光标，形成每格一动画的节奏
- **教训**：键盘输入有两条路径——NoteCell `input` 事件（路径 A，有动画/声音/队列）与 document `keydown` 直接写入（路径 B，无动画）。`preventDefault` 会切断路径 A。document 级监听器处理音符字符时必须走 `onNoteInput`，不能直接 `setNote`
- **验证**：`pnpm exec vue-tsc -b` 通过；dev server 5174 HMR 刷新即生效
