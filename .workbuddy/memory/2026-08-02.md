- 新存储格式：`[#b]?[.,]?[1-7]`，例如 `.1`/`,1`/`#.1`/`b,3`。
- 改动文件：
  - `src/core/types.ts`：`parseNoteValue`（从开头解析八度修饰符）、`isValidNoteValue` 正则、注释、新增 `migrateNoteValue`（旧格式→新格式，幂等）。
  - `src/core/note-map.ts`：`parseNote` 正则改为 `/^(#|b)?(\.|,)?([1-7])$/`，解构顺序调整。
  - `src/components/NoteCell.vue`：`onInput` 拼接改为 `prefix + octave + char`。
  - `src/components/HelpDialog.vue`：记谱示例改为 `,1`/`.5`。
  - `src/composables/useImportExport.ts`：导入时对旧格式音符调用 `migrateNoteValue`（兼容旧 `.subor.json`）。
  - `presets/*.subor.json`：7 个预设全部迁移为新格式。
- 验证：`vue-tsc -b` 通过；`vite build` 通过（需 `GENIE_TRASH_DIR` 指向可写绝对路径以绕过沙箱 trash 拦截）。
- MIDI 输出对等价音符保持不变（仅字符串表示顺序变化）。

## 修复 NoteColumn.vue 的 TS 类型错误
- 原因：`v-for="(note, voice) in props.data"` 中 `voice` 推断为 `number`，与 `NoteCell.voice: VoiceIndex` 及 emits 签名（`VoiceIndex`）不匹配，触发 `noteInput`/`noteBackspace`/`noteDelete`/`cellFocus` 多处报错。
- 修复：改为 `v-for="v in VOICES"`，用 `v.index`（`VoiceIndex` 类型）替代，避免用 `as` 屏蔽；`:value="props.data[v.index]"`。
- 验证：`vue-tsc --noEmit -p tsconfig.app.json` 零报错。

## 修复修饰符输入直接"发射"的 bug

### 问题
输入 `#`、`b`、`,`、`.` 时直接被当作独立字符提交并跳格，而非暂存等待数字拼合。

### 根因
NotationGrid 的 `document.keydown` 监听器（Path B）对每个合法字符调用 `preventDefault` + `commitNoteChar`，绕过了 NoteCell 内部的修饰符暂存逻辑（`pendingAccidental`/`pendingOctave` refs，Path A），导致 Path A 成为死代码。

### 修复方案：将暂存逻辑提升到 NotationGrid
- **NotationGrid.vue**：
  - 新增 `pendingAccidental`/`pendingOctave` ref + `clearPending()` 
  - `onDocumentKeydown` 字符输入分三类处理：
    - `#`/`b` → 暂存（后者覆盖前者），不提交，不启动长按重复
    - `.`/`,` → 暂存（后者覆盖前者），不提交，不启动长按重复
    - `1-7`/空格/`-` → 拼合修饰符后 `commitNoteChar`；空格/`-` 有修饰符时忽略
  - Backspace：先清 octave → 再清 accidental → 都空才删前一格
  - Delete：有修饰符时清除，否则删当前格
  - 长按重复只对可提交字符启动，重复原始字符（不含修饰符）
  - `clearPending` 触发点：`onCellFocus`、`handleArrowKey`、`isPlaying` watch、`commitNoteChar` bail
  - 模板传 `pendingAccidental`/`pendingOctave`/`pendingVoice` 给 NoteColumn（仅 cursor 列）
- **NoteColumn.vue**：新增三个 pending props，按 `pendingVoice` 匹配透传给对应 NoteCell
- **NoteCell.vue**：
  - 移除内部 `pendingAccidental`/`pendingOctave` refs，改用 props
  - `onInput` 简化为安全网（重置受控值 + 非法输入抖动），不再做暂存
  - `onKeydown` 移除 Backspace/Delete 的修饰符处理（已由 NotationGrid 接管）
  - `onBlur` 移除 pending 清除（已由 NotationGrid 管理）
  - `onBackspace`/`onDeleteKey` 函数移除（死代码）
- 验证：`vue-tsc --noEmit` + `vite build` 均通过

### 修饰符重复输入改为覆盖语义
- 原逻辑：同类型修饰符已暂存时，重复输入被忽略（无响应）
- 新逻辑：直接覆盖赋值——输入 `,` 后再输 `.`，`, ` 被替换为 `.`；`#` → `b` 同理
- 改动点：NotationGrid.vue `onDocumentKeydown` 中 `#`/`b` 和 `.`/`,` 分支移除 `if (!pending...value)` 守卫，改为无条件赋值

### 中文输入法全角标点自动转换
- 场景：用户忘记切换输入法，打出全角 `，`(U+FF0C) / `。`(U+3002)
- 修复：`onDocumentKeydown` 中 `const char = e.key` 处加三元映射，`，`→`,` / `。`→`.`，下游逻辑无需改动
- **补充修复**：上述方案在 Windows 中文 IME 下无效——IME 拦截 keydown（`e.key === 'Process'`，长度≠1），字符仅通过 `input` 事件到达 `<input>` 元素
  - NoteCell `onInput`：检测 `input.includes('，')`/`includes('。')`，转换为半角后 `emit('input', ',')` 转发给 NotationGrid
  - NotationGrid `onNoteInput`：开头拦截修饰符字符（`#`/`b`/`.`/`,`），设置 `pendingAccidental`/`pendingOctave` 后 return，不进入 `processInput`
  - keydown 中的全角映射保留（belt-and-suspenders：部分浏览器/IME 可能直接给出 `e.key === '，'`）
