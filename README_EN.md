## Project Introduction

SUBOR Music Board is a browser-based, retro-style music creation app. It uses numbered notation (jianpu) as its core notation system and provides a visual grid editor for three independent voices — *lead*, *chord*, and *bass* — synthesized in real time via the Web Audio API using square and triangle waves. Every sound is generated by code; no external audio files are needed for composing, previewing, or exporting.

Typical use cases:

- Music education and numbered-notation introduction
- Game / retro (FC, 8-bit) style BGM composition
- Quick sketches and prototypes of electronic music

---

## Features

- Three-voice numbered-notation editing (lead / chord / bass, square / square / triangle waves), each column mapping to one beat.
- Real-time, code-only audio synthesis via Web Audio API (no third-party audio libs).
- A responsive grid editor with direct keyboard input that auto-wraps and expands columns to fit the viewport.
- Playback controls with play / pause / stop and loop, plus live tempo and key changes during playback.
- Six preset tempo steps and five selectable major keys.
- Import / export in the `.subor.json` format for sharing and reuse.
- Built-in preset songs (Jingle Bells, Twinkle Twinkle Little Star, Coffin Dance).
- FC-retro visuals via NES.css and the Press Start 2P pixel font, with quill-writing decorative animations.

## Requirements & Installation

### Requirements

- **Node.js 20 or newer** (LTS recommended)
- Package manager: **pnpm** (recommended; `pnpm-lock.yaml` is committed). `npm` / `yarn` also work.

### Installation

```bash
# 1. Clone the repository
git clone <repo-url>
cd SUBOR-Music-Board

# 2. Install dependencies (pnpm recommended)
pnpm install
# or: npm install / yarn install

# 3. Start the dev server
pnpm dev
```

After starting the dev server, open the address printed in the terminal (default `http://localhost:5173`; the port may change if occupied).

## Configuration

This project follows "convention over configuration" and needs no extra config files. Adjustable options live in:

1. **Build tooling**: `vite.config.ts` (currently registers only the Vue plugin; extend as needed). `tsconfig*.json` hold the TypeScript project config.
2. **Runtime parameters** (in `src/core/types.ts`):
   - `DEFAULT_COLUMNS`: default number of score columns (default `125`).
   - `BPM_LIST` / `DEFAULT_BPM`: tempo steps and default tempo.
   - `KEY_SIGNATURES` / `DEFAULT_KEY_SIGNATURE`: selectable and default key signatures.
   - `EXPORT_FILE_EXT` / `EXPORT_MIME_TYPE`: export file extension and MIME type.

> ⚠️ Tempo and key support only the predefined sets. When adding a new tempo step or key, you must update both `types.ts` (constants) and `note-map.ts` (MIDI mapping), otherwise notes will not sound correctly.

## Usage & Examples

### Layout

- Left panel — OPEN / SAVE / CLEAR for import, export, and clear (available only when stopped).
- Center — the three-voice notation grid; the active cursor cell is highlighted and playback progress is shown.
- Bottom control bar — key signature, tempo (`SLOW` / `FAST` stepper), and playback controls (`PLAY` / `PAUSE` / `STOP` / `LOOP`).
- Top-right `?` opens the help dialog.

### Notation Syntax

The three voices, top to bottom, are: **lead (square)**, **chord (square)**, **bass (triangle)**. Each column's three voices share one beat, and each cell is one eighth note.

| Input | Meaning |
|-------|---------|
| `1`–`7` | Middle-octave scale degrees |
| `#` / `b` | Sharp / flat, pressed before the digit (e.g. `#4`, `b3`) |
| `,` / `.` | Lower / higher octave, pressed before the digit (e.g. `,1`, `.5`) |
| `-` | Tie, extends the previous note's duration |
| Space | Rest, inserted into the current cell and shifting later cells right |

Combination examples: `#.1` (high sharp do), `b,3` (low flat mi).

### Input Rules

- Digits or `-` (tie) **overwrite** the current cell and the cursor moves right automatically.
- Space (rest) **inserts** into the current cell, shifting later cells in the same voice one step right.
- Modifiers (`#` `b` `,` `.`) must be entered before the digit to take effect; re-entering a modifier overrides the previous one.
- Grid editing is disabled during playback.

### Keyboard Shortcuts (edit mode)

| Shortcut | Function |
|----------|----------|
| `↑` / `↓` | Move cursor between voices |
| `←` / `→` | Move cursor between columns |
| `Backspace` | Delete previous cell, shift left, move cursor back |
| `Delete` | Clear current cell, cursor stays |
| `Ctrl` / `Cmd` + `I` | Import (OPEN) |
| `Ctrl` / `Cmd` + `S` | Export (SAVE) |

### Tempo (BPM) & Key

- **Tempo steps** (cell duration = `30 / BPM` seconds):

  | Step | BPM | Cell | Note |
  |------|-----|------|------|
  | 0 | 60  | 0.500s | Slowest |
  | 1 | 75  | 0.400s | Slow |
  | 2 | 90  | 0.333s | Default |
  | 3 | 105 | 0.286s | Moderately fast |
  | 4 | 120 | 0.250s | Allegro |
  | 5 | 135 | 0.222s | Fastest |

- **Key**: Five major keys — `C` / `D` / `F` / `G` / `A` (shown as `1=C` etc., meaning the tonic); default is `C` major.

### Example: Import a Preset

The `presets/` directory ships with sample scores:

- `jingle-bell.subor.json` — Jingle Bells
- `twinkle-star.subor.json` — Twinkle Twinkle Little Star
- `coffin-dance.subor.json` — Coffin Dance

Steps:

1. Click **OPEN** on the left.
2. Select `presets/jingle-bell.subor.json`.
3. Click **PLAY** to listen.

### File Format (`.subor.json`)

Exported files are JSON with the following structure:

```json
{
  "version": "1.0",
  "title": "示例曲",
  "description": "可选简介",
  "bpm": 90,
  "keySignature": "C",
  "score": [
    ["3", "1", "1"],
    ["3", " ", " "],
    ["3", "3", "5"]
  ]
}
```

`score` is an array of columns; each column is a `[lead, chord, bass]` triple of notation strings. On import, fields and value ranges are validated, and invalid files trigger an error message.

## Testing & Build

### Common Scripts

```bash
pnpm dev       # Dev server with HMR
pnpm build     # Type-check + production build (vue-tsc -b && vite build)
pnpm preview   # Preview the production build
```

### Build Notes

- The build runs `vue-tsc` type-checking first, so **type errors fail the build** — fix them before building.
- Output goes to `dist/` as static assets, deployable to any static host.
- Assets in `public/` and `src/assets/` are handled by Vite automatically.

### Testing

No automated test framework is configured yet (no `vitest` / `jest`). It is recommended to add unit tests for `core/` (especially `note-map`, `types`, `sequencer`) to guard note mapping and scheduling logic, and to wire `pnpm build` into CI as a type/build gate.
