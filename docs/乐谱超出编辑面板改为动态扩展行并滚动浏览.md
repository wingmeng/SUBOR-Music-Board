修复乐谱过长被裁剪的问题（此前：导入时 `loadScore` 用 `Math.min(length, DEFAULT_COLUMNS)` 截断到 125 列；渲染时 `NotationGrid` 的 `visibleScore` 用 `slice(0, visibleColumns)` 裁剪超出可视区域的列；输入时 `advanceToNext` / `handleQuillAnimationEnd` 受 `score.length` 限制无法越过末尾）。

新行为按用户要求：**初始化时仍按「不产生滚动条」的可视容量决定行数**，只有乐谱内容真正超出现有行后才生成新行并撑出滚动条。实现要点：

1. **数据层（useNotation.ts）**：`loadScore` 完整加载不截断（不足 DEFAULT_COLUMNS 仍补齐）；`setNote` / `insertNoteAt` / `moveCursor` 在列索引超出当前长度时自动追加空白列，输入越过末尾即生成新列/新行；原 `ensureColumns` 替换为 `syncColumns(capacity)`——不足补齐铺满、超出且尾部全空则裁掉空白尾（不删音符、保留光标列）、超出且含真实音符则保留全部（滚动）。
2. **渲染层（NotationGrid.vue）**：删除 `visibleScore` 切片，`v-for` 全量渲染 `score`，靠 flex-wrap 自动换行成多行，超出容器高度由 `.board-scroll`（overflow:auto + scrollbar-gutter）承接滚动条；`visibleColumns` 语义变为「可视容量」，仅用于 `syncColumns` 数据对齐；`advanceToNext` / `handleQuillAnimationEnd` 移除 `score.length` 守卫；`focusCell` 在目标列尚未渲染（数据刚扩展）时延至 `nextTick` 聚焦，浏览器自动滚动到可见区域。
3. **编排层（App.vue）**：`visibleColumns` 的 watch 改为无条件调用 `syncColumns`；导入（`onImport`）与清空（`handleClearConfirm`）后同样调用 `syncColumns` 对齐可视容量，清空后恢复「不产生滚动条」的干净板面。
4. **其他**：`sequencer.ts` 中「固定有 DEFAULT_COLUMNS(150) 列」的过时注释更新为动态列数描述。

行为验证（类型检查 `vue-tsc -b` 通过；生产构建因沙箱安全删除无法清空 `dist/`，改用 `vite build --outDir dist-verify` 验证打包通过）：

- 初始：乐谱列数对齐可视容量 → 板面正好铺满、无滚动条；
- 输入越过最后一格：moveCursor 自动扩展 → 新行出现 → 滚动条出现；
- 导入长谱（> 可视容量）：完整保留，滚动浏览；
- 导入短谱：补齐到可视容量，无滚动条；
- 窗口缩放：变大补齐、变小且含内容则保留全部（滚动）。

已知取舍：`syncColumns` 裁剪「空白尾部」时，若用户刻意在可视区之外只输入休止符（空格）且该区全部为空格，会被当作空白尾部裁掉（与既有「末位丢弃」语义一致，播放有效长度本就跳过尾部空白）。
