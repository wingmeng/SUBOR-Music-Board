播放中点击调号或速度控件曾出现两类问题：①节奏变乱、播放指示器与实际音频不同步；②连续多次点击产生多个音频叠加混响、整体状态混乱。

## 根因
旧实现（setKeySignature/setBpm 命中 playing 时）采用「stopFrom(cutoffTime) 保留当前列 + 从下一列重排」：
- cutoff 由 `lastScheduleBaseTime` / `lastScheduleStartCol` 推算，快速连点时计算漂移，部分旧振荡器未被杀掉，与重排后的音符叠加 → 混响；
- 指示器沿用旧 playbackWallStart 基准、音频按新基准排布 → 永久错位；
- `_rescheduling` 同步标志每次调用同步复位，对跨事件循环的快速连点无效。

## 新方案（用户确认的策略）
1. 命中 playing 时，每次变更立即 `getMusicEngine().stopAll()` 丢弃所有正在播放/已调度的音，杜绝叠加；
2. 用 120ms 防抖等待「调整完成」（连续点击/拖动只重置定时器，不反复调度）；
3. 防抖触发后 `restartFromCurrentPosition()` 依据虚拟时间算出当前指示器列，用新调号/速度从该列整体重排；`playbackWallStart` 与 `scheduleAllNotes`（baseTime = engine.currentTime + 0.1）对齐，指示器在约 100ms 后与该列音频同时发声，恢复音画同步。

## 实现要点
- 新增 `restartTimer`/`restartDelay=120`/`lastUiColumn` 实例字段，取代 `lastScheduleBaseTime`/`lastScheduleStartCol`/`_rescheduling`；
- 防抖定时器在 `pause()`/`stop()` 中清除，避免暂停/停止后误重启；
- UI 定时器列号下限钳制为 0（修复 `displayCol` 可能越界为 -1 的隐患）；
- `music-engine.ts` 的 `stopFrom` 现无人调用，保留为无害公共工具未删。

## 验证
- vue-tsc 类型检查通过；vite build 打包成功。
- agent-browser 浏览器实测（dev server 5174）：播放中连续改速度（120→135→90）与调号（C→♭B→D），state 全程 playing、指示器平滑推进、无异常（errs=[]），印证丢弃+从当前列重排策略有效，无混响叠加、无音画错位。

## 补充：变速时指示器跳格修复（2026-08-31）
- 现象：修复混响/错位后，调号调整正常，但点 SLOW 播放进度"后退几格"、点 FAST "快进几格"。
- 根因：`restartFromCurrentPosition()` 用 `getNoteInterval()`（已是新 BPM 的间隔）除以"墙钟已播秒数"计算当前列，而 `playbackWallStart` 仍是按旧间隔建立的映射。间隔变小（FAST）→ 列号算大 = 快进；间隔变大（SLOW）→ 列号算小 = 后退。调号不变间隔，故不受影响。
- 修复：`setBpm` 在改 BPM 前先按旧间隔定位当前指示器列，改完后立即按新间隔重映射 `playbackWallStart` 到同一列（`playbackWallStart = now - currentCol × 新间隔`），使指示器在 120ms 防抖与重启期间保持在原列、平滑推进。
- 实测（页内 100ms 采样，48 列谱）：SLOW(120→105) 指示器 22→23 平滑；FAST(105→135) 24→24/25 平滑；state 全程 playing，无后退/快进（仅重启对齐时有 1 列、100ms 的瞬时微抖动，与调号行为一致）。
