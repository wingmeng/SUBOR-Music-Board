# 播放跟随滚动（长乐谱自动定位播放头）

日期：2026-09-01

## 背景

乐谱列数超出单屏容量（`.board-scroll` 出现滚动条）后，播放头会跑到可视区之外，
用户需要手动拖滚动条才能看到当前播放位置。典型场景：350 列的《千与千寻-永远同在》。

## 实现

改动集中在 `src/components/NotationGrid.vue`：

- 新增常量 `PLAY_SCROLL_LOOKAHEAD_ROWS = 1`（播放头行贴底时额外露出的行数）。
- 新增 `scrollPlayheadIntoView(col)`：
  - 无滚动条（`scrollHeight <= clientHeight + 1`）直接返回，短乐谱零扰动。
  - 用滚动容器与列的 `getBoundingClientRect()` 差值换算行位置 —— 不依赖
    `offsetParent`，因为 `.board-scroll` 为 static 定位。
  - 行在可视区上方 → 行顶部对齐容器顶部；行贴底/越界 → 向下滚动并多露 1 行。
  - 向下用 `behavior: 'smooth'`，向上（循环回卷到第 0 列）用 `'auto'`，避免长距离平滑动画拖尾。
- 触发时机：
  - `watch(() => props.currentPlayColumn)`：仅 `isPlaying` 为真时跟随（停止/暂停不动滚动位置）。
    只在行越界时改动 `scrollTop`，行内逐列推进为空操作。
  - `watch(isPlaying)` 变 true 时 `nextTick` 立刻定位一次：序列器 UI 回调由 50ms
    定时器驱动、`state = 'playing'` 先于首列回调，续播 / seek 后播放可立即看到当前列。

## 行为取舍

- 停止（STOP）不回滚到顶部：`stop()` 会把 `currentColumn` 置 0，若跟随会打断正在
  底部编辑的用户，故只在播放中跟随。
- 播放中用户手动滚动后，下一次翻行仍会被拉回播放头行 —— 保持"播放头始终可见"这一
  单一规则，不引入临时挂起的额外状态。

- `pnpm dev --port 5174` 编译通过（SFC 正常产出）。
